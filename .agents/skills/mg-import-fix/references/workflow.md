# MG 新测试集处理工作流

本文是阶段、授权、Gate 与完成条件的唯一执行事实源；[流程图](../docs/workflow.svg) 是人类概览。初始化细节见 [setup.md](setup.md)，修复细节见 [repair.md](repair.md)，按进入阶段读取。

## 输入、范围与批次记录

从用户指定的一个 `.mg` 开始，完成 MasterGo 导入、三页基准准备、接收端修复与真实重导入，除下述仅缺字体的提前结束分支外，最后交用户验收。已有配对样本与 Figma 链接时可核实后从相应阶段续作，不强制重建。仅咨询或维护技能不触发桌面操作；用户明确只要求初始化或单层修复时遵守该范围。

路径不明确时先查用户指定位置、仓库和 Downloads 的 `.mg` 候选（排除依赖与缓存），按文件身份核实；多个候选无法消歧才询问，不仅按修改时间猜测。保留输入文件，不覆盖或提交私有样本。

开始桌面操作前提醒将切换 MasterGo / Figma 前台，建议期间尽量不要操作电脑；这不是额外确认。Computer Use 先读工具 API 文档。精确 Figma 树/几何调用前加载 `figma:figma-use`；新建文件前加载 `figma:figma-create-new-file`。不猜工具入口和元素索引。

首次桌面操作前，按用户时区的执行日期原子创建 `Downloads/测试集 MMDD`，重名依次加 ` 2`、` 3`，并创建 `progress.md`。尚未导入或导出时明确记为“仅日志、尚无资产”；续作沿用已核实目录，不因跨日或资产尚缺另建批次。

日志顶部只保留一份**最新状态摘要**，每次阶段、资产、验证结论或测试责任变化时同步更新：

- 当前阶段及更新时间；继续、等待、阻塞或结束原因。
- 输入与配对资产的身份、快照、实际路径；未生成的资产明确标缺失。
- 源文件/Page、Figma 文件与当前最终页链接；页面 ID 是记录时证据，操作前重查。
- 图片覆盖、几何核验、用户验收分别列结论；代码/构建检查、真实导入与待用户手测分别列状态。
- 下一步、执行者及未验证项；用户结束时保留测试责任，不把待测改为通过。

摘要后追加带时间和时区的事件记录，包括操作、证据、差异、导出端候选及 Gate 答复。错误判断在原记录处显式标“已更正”并指向后续证据，不只在末尾追加相反结论。续作或工作区恢复/清理后，重新核实源文件、唯一 Page、插件、实际资产与 Figma 页面 ID；历史路径和完成记录不能代替当前证据。

## 1. MasterGo 主页导入与加载

通过 Computer Use 打开 MasterGo，回到主页，使用当前可见的导入入口导入指定 `.mg`。等待导入完成，再打开新文件，等待页面列表和画布加载稳定。核对文件名、导入结果和实际 Page 列表，不把上传完成当成设计已加载。不要求应用只开一个文件，也不关闭其他文件来满足条件。

## 2. Gate：完整文件只有一个 Page

读取完整 Page 列表，恰好一个 Page 才继续。超过一个 Page 时停止后续导出与 Figma 初始化，告知当前页数、页名，请用户处理为单 Page 后继续；不得自行删除、合并或只选一页绕过 Gate。等待用户处理后重新检查同一文件和完整页列表，不能以等待时间或用户口头说完成替代核验。零页、加载未完成或无法确认列表时报告阻塞，不能假定通过。

## 3. 在 Downloads 保存同一快照

沿用首次操作前已创建并核实的批次目录，将状态从“仅日志”逐项更新为实际已保存资产；不覆盖或混入旧批次。

通过 MasterGo 原生保存/导出取得当前单 Page 文件的 `.mg`，再用 SendToFigma 的全页/所有 Page 导出取得 v2 ZIP，都保存到本批次目录。不能用原始输入代替用户处理后的原生快照，不能以改扩展名或 CLI 转换代替原生导出，也不能用选中图层代替全页。确认文件非空、ZIP 可读取且含目标 Page，记录实际路径；保存框关闭不等于保存成功。

从此到图片完成不编辑源设计；若源变化，重新生成配对资产和相关基准，不混合快照。图片首选经 Python 系统剪贴板逐层保存到本目录 `images/`，用稳定序号关联源根层；操作细节见 [images.md](images.md)。

## 4. Figma 三页准备

### Figma 团队选择

用户已授权自动选择具备编辑席位的非 Free 团队，Student 属于候选；用 whoami 核实实际 tier、席位与 plan key，排除 Free/Starter 和仅 View 席位。沿用会话中已选团队；在本用户环境中优先「实在 Agent」，其不可用时选择当前符合条件的团队。多个合格团队本身不新增确认 Gate；若当前工具仍要求用户明确选择，先沿用本会话已有选择，仅在无可复用选择时询问。没有合格团队或创建后权限核验失败时报告具体阻塞。

### 插件运行隔离

每次实际导入都保持 Figma 及目标文件在前台，直至插件明确成功；期间不并发调用 `use_figma` 或其他 Figma API，可做不操控 Figma 的本地分析。短时停滞按[桌面状态恢复](#桌面状态恢复)处理，不重复提交。成功后关闭插件，再通过 API 列实际页面 ID、命名并取证；此规则同样适用于初始化和接收端重导入。

### 三页操作

按 [初始化细节](setup.md) 新建本批次 Figma Design 文件，既有标签页不构成阻塞。分别真实导入 MG、ZIP，创建 `<Page>_mg` / `<Page>_zip`，随后必需完成 `<Page>_image`，不在两页后停下询问图片授权。

`_image` 只能来自 MasterGo 原生渲染。首选按根层保存原生剪贴板 PNG，再 Duplicate `_zip` 为 `_image`，Python 逐张载入剪贴板并在 Figma 替换对应根层。沿用用户已明确给予的 Python 读写剪贴板授权；其他 UI 操作仍遵守当前 Computer Use 能力和权限。按 [图片流程](images.md) 核对覆盖、顺序与几何，不在图片阶段另设授权 Gate。保留初始导入页作为基准，后续修复创建可辨认的验证页。

分别报告图片覆盖完成情况、已验证几何和逐层边界例外；全根层成为图片不等于全页像素级对齐。未知边界标为几何待核验，缺失图片标为覆盖未完成，不将二者混写为成功。

## 5. 释放 MasterGo 资源

确认 MG/ZIP 资产已保存、三页可读取、所有可导出的原生图片已传入且对应几何核验完成后，关闭本次 MasterGo 文件并退出 MasterGo以减少资源占用。退出出现未保存改动提示时先核实，不能丢弃用户其他文件的改动；无法安全退出则保留应用并说明。采集时就按 PNG 与源逻辑框差异建立待取证清单，仅对未解决边界补最少必要的原生证据；覆盖完成但几何仍需源端取证时不提前关闭。后续默认只在 Figma 与本地仓库操作；ZIP／导出端修复不自动重新打开 MasterGo；只有用户另行要求桌面测试或补充原生证据时才重开。

## 5a. 三页核验后：仅缺字体可提前结束

测试集可能已过时，不能根据旧问题标注默认认定仍需修复。三页创建和图片核验完成后，分别将实际 `_mg`、`_zip` 与 `_image` 做整页对照：若剩余差异仅是**字体缺失导致的文本差异**，可按用户授权提前结束，无需进入修复循环，也无需再等待第 7 步的用户验收 Gate。

提前结束须有当前证据：记录受影响文本节点、所需 font family/style、桌面 Figma 或实际导入插件的缺失/替代字体报告，以及三页对应区域的对照结果，确认两种导入均无其他差异。MCP 环境单独报缺字体不够；导入器漏读字体（包括字体列表/glyph 索引解码错误）、匹配错误、文字内容/样式丢失、空字符串实例覆盖丢失、嵌套 Group 收尾偏移、来源不明的布局变化或图片边界未核实，都不能直接归为字体缺失。测试集过时只是检查动机，不是提前结束依据。

满足条件时保留三页与配对资产，按第 5 步安全释放源端资源，并在 `progress.md` 与交付中写明“提前结束：仅剩已核实的缺失字体文本差异”，附页面链接、缺失字体/节点清单和已执行检查。不标记为“完全一致”或“用户已验收”，不为该分支强制安装字体、修改代码、构建或重复导入；导出端候选仍不自动实施。任一导入页有其他差异或原因尚不确定，则继续对应取证/修复，不触发此分支。

## 6. 接收端修复循环

按 [修复细节](repair.md) 分诊、修复、回归、构建并分别真实重导入 MG / ZIP，逐屏与 `_image` 核对，直到约定范围内可修问题消失。`_image` 是原生渲染基准；ZIP 只提供结构证据。只有 MG 错优先查解码器；两边同错先查相关 record，一致时转 importer。检查 deep prop、record 级语义及 importer 在真实树上的增删，不能只看具名计数。原生证据可证明修正后的 MG 比旧 ZIP 更准确；不得为清零 compare 去拟合错误 ZIP，必须逐项解释剩余或新增差异。

默认可修改接收端 MG 解码器、ZIP 解析/导入和共同 importer；共享代码改动需检查对发送端的影响。**SendToFigma 导出算法优化先不实施**，不以共享代码绕过该边界。发现导出端问题记录源证据、ZIP 缺失/错误字段、影响节点、建议改动与验证方式，继续完成独立的接收端修复。不得给 importer 填入无依据的猜测来遮掩导出缺失。

“异常文字除外”只覆盖已逐项列出且有证据的字体缺失、异常源文字或平台文字渲染差异；保留截图和原因供最终确认。仍修复可归因于解码/导入的内容丢失、字号、行高、字距和文字布局错误，不默认豁免所有文字问题。

保留任务开始时未提交代码与实际基线，不用 stash。功能变更执行相关测试、两端构建；接收端修改用已有配对资产真实重导入，ZIP／导出端修复的原生重导出及新 ZIP 端到端验证按第 7 步交用户手动测试；导出端构建不等于获准修改其算法。已通过的无关检查不重复执行，新增修改或退化再跑相关检查。文档记录实际结果，不拿历史残差充当本轮验证。

遇到明确导出缺口，可完成其他修复后带具体残差进入最终 Gate；遇到工具/基准阻塞则报告未完成项并等恢复，不宣称还原完成。不以第一版、一次结构比较通过或一个局部截图结束整页闭环。

## 7. Gate：用户验收与导出端选择

在已授权的接收端实现、回归和真实视觉验证完成后，提供可直接查看的 Figma 文件及最终 MG / ZIP / image 页链接、前后热点对比、验证结果、异常文字清单和其他残差。此时状态为“待用户验收”，不能代替用户确认正常。

请用户确认效果是否正常；有导出端候选时，同时列出具体候选及影响，询问是否实施。没有候选则不空问导出优化。等待答复，不把沉默当批准。效果不通过时按用户指出的差异返回修复循环。

用户暂不做导出端时，保留清单并将该项标为延期；如果用户接受当前效果及已披露例外，可结束为“已验收，导出端延期”，不能称完全一致。用户批准具体导出端优化后才修改 SendToFigma。ZIP／导出端修复完成代码、相关自动化检查和两端构建后，交用户手动执行 MasterGo 导出与 Figma 导入对照；不自动启动或重开 MasterGo，不为此发起桌面恢复，也不自动执行新 ZIP 的端到端桌面测试。现有样本不足时明确证据缺口，等待用户提供测试结果或新 ZIP，不能把手动测试视为阻塞而反复重试。

交付列出变更、构建产物、检查结果及具体测试检查点（目标节点/区域、操作和预期结果），明确现有画布仍来自哪个旧资产、哪些效果尚未更新，状态写为“实现与自动化检查完成，待用户手动测试”，不声称原生导出或画布效果已通过。建议用户保留旧 ZIP，使用同一源快照导出版本化 ZIP 后与已验证 image 对照；收到新资产或反馈后按授权范围继续分析和修复。仅在用户另行明确要求时恢复自动桌面导出验证。

## 完成与恢复

**用户明确说“本次流程结束”时停止继续修复和桌面测试。** 更新最新状态，保留产物、未验证项及测试责任，直接交付，不再请求另一个结束确认；“结束”不等于用户确认全部像素效果通过。此指令优先于修复循环、等待验收与恢复步骤。应用状态只按最后实测记录，不因曾退出就宣称当前仍已关闭，也不为收尾自行操作用户窗口。

ZIP／导出端修复可按第 7 步交付并等待用户手动测试；这一阶段无需代理生成新 ZIP 或更新 Figma 页，但效果确认仍以用户反馈为准。满足第 5a 步时可按该分支提前结束；其他情况的完整完成须有配对资产、可信 `_image`、最新真实导入的 MG / ZIP 页、已执行检查及无未解释退化、用户效果确认，以及导出端候选的明确决定。仅清理确认属于本轮的临时节点、失败页和中间验证页，保留原基准与最终成功页。用户原有文件、窗口及未提交代码不作附带清理。

失败续作读取批次记录并重新列页面 ID；先确认导入是否仍运行再重试。桌面状态异常先执行下述恢复，再判断是否阻塞；同一故障没有新证据不循环重试。说明缺工具、权限或基准等具体阻塞、已保留产物及恢复条件。Gate 2（单 Page）与 Gate 7（最终确认）是常规流程中的用户参与点；第 5a 步是用户已授权的提前结束例外，图片阶段不新增 Gate。


### 桌面状态恢复

先区分异步加载、取证延迟、截图异常与真实操作失败。首次点击后 AX 未变化、倾斜缩略截图或一次静态结果都不足以判失败；使用工具内建等待并重新读取 AX/截图。可靠 AX 已显示可操作弹窗时可据此继续，不必等待异常截图恢复。加载或进度仍变化就继续等待，不重复提交，不硬编码任意长等待，也不以工具返回耗时充当加载耗时。

AX 与截图持续不一致、控件暂空、快捷键无响应或窗口长期不更新时，先尝试唤起目标应用及文件窗口，再重新核验，不直接把恢复交给用户。窗口休眠或后台节流仅为可能原因，未经验证不写成已确认根因。

1. 使用当前 Computer Use 工具支持的应用激活方式或当前 UI 中实际存在的原生窗口菜单，把目标应用及目标文件窗口带到前台；例如可用时使用 Window → Bring All to Front 或目标窗口条目。`getApp`、AX 读取或一次 Raise 的返回本身不能证明已处于前台。保持现有窗口尺寸，不靠反复全屏或最大化唤醒。
2. 唤起后重新读取 AX / 截图，核实文件、页面、选区和插件状态，丢弃旧控件索引。遵守工具的等待机制；仍显示加载中或进度变化时继续等待，不重复发起导入、导出或粘贴。
3. 状态恢复且前一步确实未完成时，用新控件信息重试该步骤一次；若前一步已经完成，直接续作下一步。成功后自动继续已授权流程，不重复索取确认，并记录唤起方式、前后状态与结果。
4. 已尝试前台唤起、重新取证和有依据的重试后，仍无法可靠识别或操作，才报告具体阻塞与恢复需求。记录实际尝试及未完成项，不把多次读取同一旧状态算作多次恢复，也不因用户建议“可能休眠”而直接更改系统休眠设置。
