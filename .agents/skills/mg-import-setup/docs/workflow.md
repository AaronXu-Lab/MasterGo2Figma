# MG 导入对比初始化工作流

本文是执行事实源；[workflow.svg](workflow.svg) 是面向人的可视化投影。

## 产物与范围

在用户 Downloads 目录保存同一次源设计快照的 `.mg` 和 SendToFigma ZIP；在一个新建 Figma Design 文件中生成 `<源 Page 名>_mg`、`<源 Page 名>_zip`。用户选择图片阶段后再添加 `<源 Page 名>_image` 和每个根图层的 MasterGo 原生图片；优先通过剪贴板传递，只有文件导出回退路径才需要图片目录。路径使用实际用户 Downloads 的绝对路径，文件名带同一批次标识，遇到同名文件另取名，不覆盖旧测试资产。私有设计文件不复制进仓库或提交 Git。

## 1. 起始 Gate：先检查，再写入

通过 Computer Use 检查 MasterGo、Figma 的窗口和标签页，包括可见的浏览器文档标签。必须确认：

- MasterGo 只打开一个设计文件，完整页面列表恰好一个 Page；不能把“只选中了一个 Page”当成单 Page。
- Figma 没有打开任何设计文件；主页、文件列表可以存在，但空白设计文件也算已打开文件。
- 文件身份和页名可明确读取，两个插件的入口可用；无法核实的状态不视为通过。

记录源文件名、Page 名和当前状态。Gate 不通过或无法检查所有相关窗口时，停止导出和新建，说明具体不满足项，让用户调整后重新检查。不要自行关闭其他文件、删除多余 Page 或改变源设计来满足 Gate。这是本技能明确的起始条件。

## 2. 在 MasterGo 保存同一快照

通过 MasterGo 原生菜单将当前文件保存或导出为 `.mg` 到 Downloads；使用现场可见入口，不能用 ZIP 改扩展名、CLI 转换或缓存文件代替原生保存。

运行 SendToFigma 插件，选择“所有 Page”的实际等价选项，导出 ZIP 到同一 Downloads 目录。即使只有一个 Page，也不能用“选中图层”代替全页导出。记录两个实际路径并确认下载/保存完成、文件非空、ZIP 可读取且包含该源 Page。不要只凭文件选择对话框关闭或插件开始进度就判定成功。

两次导出之间不编辑源设计。若检测到源变更，重新生成成对资产，避免混用两个快照。导出失败时保留已完成资产并报告失败环节，不用旧 Downloads 文件冒充本次产物。

## 3. 创建 Figma 对比文件并分别导入

通过 Computer Use 在 Figma 新建一个 Design 文件，使用本次 `.mg` 文件的完整文件名去掉末尾 `.mg` 后命名（例如 `测试b端-20260919-182243.mg` 对应 `测试b端-20260919-182243`），不额外添加“导入对比”等字样，记录链接或 file key。运行接收端 ReceiveFromMasterGo 插件：

1. 先记录当前页面列表，再选择本次 `.mg`，导入唯一源 Page，等待明确完成；通过前后页面列表识别新增页并命名为 `<源 Page 名>_mg`。
2. 在插件实验室中启用“启用 ZIP 导入”（本次导入所需设置属于已授权操作），返回主界面选择本次 ZIP，导入唯一源 Page。等待完成，重新列出页面并将新增页命名为 `<源 Page 名>_zip`。
3. 两次导入分别进行，不使用多文件合并入口，以免页面来源混淆。不要复用旧 page ID。只清理本次新建文件自带且确认空白的默认页；保留有内容的页。

两次导入均明确完成后关闭接收端插件，确认插件面板消失、画布可见，再验收和交付；不要在仍在导入时关闭。若图片阶段再次打开了插件，完成后同样关闭。

读取实际页面和根图层清单，记录名称、顺序、可用的源 ID、位置、尺寸和变换，必要时用 Figma API 精确读取。重复名称使用源 ID、根顺序和几何信息共同对应，不按同名随意匹配。确认两个后缀页存在且可查看；源非空但导入页空白、失败或仍在运行时不得声称完成。字体/缺图警告、缺失根图层和布局差异按实际记录，差异本身是测试结果，不在这里修复或挪动样本。

### 已验证的操作经验（2026-09-19 试跑）

- 仓库接收端目录名为 `ReceiveFromMasterGo`，Figma 中实测显示为 **MasterGo Importer**。使用 `Command+K` 搜索此名称，选中正确结果后按 `Return` 启动；仅点击搜索结果曾未启动，必须以插件面板出现为成功依据。以后界面名称变化时按实际入口核实。
- 原生文件选择器：先打开并观察对话框，再按 `Command+Shift+G`，填入本次文件绝对路径，按 `Return` 跳转；观察定位完成后再按 `Return` 确认打开。不要把打开对话框和路径快捷键抢在同一未就绪状态中发送。
- 插件按钮或系统对话框的 AX 点击没有生效时，实测可通过 `Tab` 聚焦目标、`Return` 激活。先核实焦点和标签，再发送按键；界面状态改变后重新读取，不复用旧索引。
- MasterGo 原生 PNG 文件导出成功过，但 Figma “置入图片”选择完文件后仍需要画布放置，不能把文件选择器关闭当作图片已导入。上次图片流程未完成，不把这条路径记录为端到端成功。

## 4. 必需阶段完成后停止并询问

交付两个资产的绝对路径、Figma 文件链接、两个页面名称，以及导入警告或未完成项。必需阶段成功后，到这里结束操作，并询问：“是否需要将 MasterGo 当前 Page 的每个根图层原生导出为图片，并添加到 Figma 的 _image 对比页？”

这是用户指定的阶段边界：未得到肯定答复时，不导出图片、不创建 `_image` 页。拒绝则完成整个流程；未答复保持等待。完整会话中已明确要求图片时沿用授权，无需重复询问。询问时说明该阶段边界来自本技能并链接本工作流。

## 5. 用户选择后：生成原生图片基准

继续前确认仍是同一 MasterGo 文件和 Page、同一 Figma 对比文件，且源设计没有改变。无法确认或源已变化时报告快照不一致，让用户决定是否重新初始化，不直接混入新基准；此时 Figma 已打开目标文件是预期续作状态，不重新要求“没有打开文件”。

列出源 Page 的所有直接子节点，逐个记录源 ID（可获取时）、名称、顺序、x/y、宽高和旋转/变换，匹配 `_zip` / `_mg` 中的对应根图层。

### 首选：复制为图片，再替换粘贴

这是用户提供的快捷流程，尚未完成自动化实测。首次执行先用一个普通、无外溢根图层验证，确认确实粘贴为图片、位置和尺寸正确后再批量继续：

1. 在 Figma 复制 `_zip` 页作为 `<源 Page 名>_image`（若 `_mg` 的对应关系更完整，可选 `_mg`）。只在新副本中操作，保留两个原始比较页。若续作时已有空 `_image` 页，可把对应根图层复制到该页并核实几何，避免重复建页。
2. 在 MasterGo 选中一个源根图层，使用 `Command+Shift+C` 复制为图片；切回 Figma，在 `_image` 页选中唯一对应的副本根图层，使用 `Command+Shift+R` 替换粘贴。每次只处理一个根图层，避免同名层或多选造成错配。
3. 检查替换结果是真实图片而非仍然保留的可编辑副本，核实图片内容、x/y、宽高、旋转及根层顺序，恢复源名称。快捷键不保证几何必然保留，偏差仍须精确校正。验证一个成功后再处理其余根图层。

若现场快捷键不可用，先检查菜单与焦点；一次针对性重试仍失败即转原生 PNG 路径，不反复尝试窗口切换。不可把未替换的副本当作完成的图片基准；报告并保留明确的未完成清单。

### 回退：原生 PNG 文件导出

使用 MasterGo 自带图层导出逐个生成 PNG，优先 1×、透明背景，存入 Downloads 本批次图片目录，以稳定序号避免重名。临时导出设置记录并恢复；不改变设计可见性、布局或内容。在 `_image` 中导入并放置图片，恢复源几何、名称及顺序。若替换路径已有部分成功，仅继续剩余根图层。

两条路径均不得使用屏幕截图、Figma 导出、MG 解码后渲染或其他绘图器替代 MasterGo 原生渲染。不要依赖默认粘贴位置、自动排列或图片像素尺寸推断最终几何。图片中已经烘焙的旋转不得再次旋转。

阴影、描边、旋转或裁切可能使原生导出边界不同于节点逻辑框：使用源逻辑框定位同名承载 Frame，图片按真实导出边界偏移放置，保持外溢可见，避免将含阴影的 PNG 强行拉伸到逻辑宽高。常规无外溢节点可直接使用图片矩形。使用实际可验证的导出边界，不能猜测偏移。

逐一核对 `_image` 与 `_mg`、`_zip` 的对应关系和几何信息。两页对应根图层几何一致时，图片对应的逻辑框位置/尺寸应与两者一致（记录数值，允许浮点误差 0.015）。若两页本来不一致，保留原导入结果，以 MasterGo 源几何作为图片基准，列出无法同时对齐的节点，不移动 `_mg` / `_zip` 来制造一致。未知边界、缺失对应层、隐藏或零尺寸节点无法原生导出时，明确列为未完成或例外，不悄悄跳过或伪造图片。

完成标准：所有可导出的源根图层都有图片及可靠对应关系，位置/显示尺寸已核对，异常逐项披露，并在 Figma 实际查看三页对应区域确认无意外缩放、额外裁切或位置漂移。交付三页名称及数量、实际采用的图片路径（剪贴板或 PNG；仅文件导出时附图片目录）、几何校验结果和剩余差异；有未解决例外时不宣称全部对齐。

## 失败恢复与操作边界

保持用户现有窗口大小与桌面布局，不为例行操作全屏化、最大化或移动窗口。上次试跑中全屏切换未解决 `noWindowsAvailable`，不将其作为默认恢复手段。优先当前窗口的 AX / 键盘操作和适用的 Figma API；遇到异常刷新状态后最多进行一次有依据的替代尝试，同一阻塞仍存在就报告具体未完成项，不循环切换窗口或反复置入。确有操作必须调整窗口时，记录必要性并在操作后恢复原状态。


记录已完成资产、目标文件链接和最新页面列表。失败后先核实插件是否已创建页面或仍在工作，再决定续作；不要盲目重试导致重复文件/页面。仅清理确认由本次失败重试产生的空页或残留，无法区分时保留并报告。缺少插件、权限、工具能力或精确几何证据时说明具体阻塞，不将初始化扩展为安装插件、修改项目代码或修复导入器。

若使用 Playwright 验证，清理阶段关闭为本次验证创建的命名会话，即使验证失败也须关闭；保留用户需要查看的目标设计文件与下载资产。
